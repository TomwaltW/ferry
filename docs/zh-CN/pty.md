# 包装终端程序

[English](../en/pty.md) · **中文**

`ferry run` 把一个完全不懂 agent 协议的命令行程序放进伪终端，让聊天可以看它的输出、
往里打字。这是实验功能，支持 Linux、macOS 和 Windows。

## 用法

```sh
ferry run [--name <name>] [--idle <ms>] [--prompt-regex <re>] -- <command> [args...]
```

例如：

```sh
ferry run --name aider -- aider --no-auto-commits
```

终端仍然是你的：程序照常在里面跑，终端切到原始模式，窗口大小变化会同步过去。
先把 `ferry daemon` 跑起来；守护进程没运行时 `ferry run` 只是一层包装，不会同步到聊天。
程序退出时，`ferry run` 以相同的退出码退出，聊天里的会话随之结束。

## 聊天里的输入怎么打进去

聊天发来的消息不会立刻打进去。`ferry run` 要等程序连续 `--idle` 毫秒（默认 1500）
没有输出；设置了 `--prompt-regex` 时，还要等屏幕最后一行匹配它。然后以括号粘贴
（bracketed paste）的方式贴入文本并回车。你在最近 2 秒内按过键的话，会等你停手再打。

之后的输出一直收集到程序再次安静，去掉颜色控制码、回车覆盖和回显的输入，
作为一条回复发到聊天。

## 参数

| 参数 | 作用 |
| --- | --- |
| `--name <名称>` | 会话在聊天里的名字，默认是命令名。 |
| `--idle <毫秒>` | 程序安静多久后才把聊天的输入打进去。 |
| `--prompt-regex <正则>` | 只有最后一行匹配时才打字，例如 `^> $`。 |

## 限制

- 不中继审批：这类程序没有发审批请求的途径。会话接入时聊天里会收到说明，
  有提示请在电脑上处理。
- 输出判断靠启发式。一直在重绘屏幕的程序永远不会「安静」，这类程序请设置
  `--prompt-regex`。
- Windows 上依赖 ConPTY，需要 Windows 10 1809 及以上；更早的 Windows 上
  `ferry run` 会提示不支持后退出。聊天输入的打字方式和 Linux、macOS 相同。
