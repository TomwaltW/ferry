# 微信入口

[English](../en/wechat.md) · **中文**

Ferry 怎么经 iLink 机器人网关跟微信说话，以及一个会话在聊天这一侧是什么样子。

## 登录

`ferry login wechat` 取二维码并在终端画出来。你掏手机的这段时间里，
它最多自动刷新三次。**用你平时说话的那个号扫**。bot 本身不是一个微信号，
不需要另找一个号来扫。

确认登录后拿到的是 bot token、bot ID，以及扫码人的 ID。最后这个就是 owner，
登录成功时两个 ID 都会打出来。
平台之后把会话作废时，守护进程会把微信标成离线、继续运行、每分钟重试一次；
重新跑 `ferry login wechat` 就能接回来。

## 命令

**只有整条消息匹配才算命令**，所以一句话里顺带提到 `/stop` 仍然是普通 prompt。
以 `//` 开头的消息会去掉一个斜杠，按普通文本处理。

| 命令 | 别名 | 作用 |
| --- | --- | --- |
| `/ls` | 会话 | 列出本聊天的会话，`▶` 是当前会话 |
| `/new [agent] [目录]` | 新建 | 新建会话；agent 省略时用 `default_agent`，目录省略时用第一个工作区根目录 |
| `/use <n>` | 切换 | 切到第 n 个会话，已停放的先恢复 |
| `/agents` | | 列出已配置的 agent 和能不能跑 |
| `/stop` | 停 | 取消当前这一轮 |
| `/close [n]` | 关闭 | 关闭会话 |
| `/mode <项> <值>` | | 设置会话选项，比如 agent 的模式 |
| `/lang <zh 或 en>` | 语言 | 切换本聊天的机器人语言 |
| `/pair <配对码>` | 配对 | 确认配对（仅审批人可用） |
| `/pull` | 收件 | 发下一批窗口关闭期间积压的消息 |
| `/file [n]` | 文件 | 重发第 n 份长输出文件 |
| `/help` | 帮助 | 命令说明 |

积压清空后 `/pull` 回复「没有积压的消息」。`/file` 不带编号时重发最近的那一份。

中文键盘怎么打就怎么认。电脑版微信开着拼音输入法时，`/` 键打出来是 `、`，
全角模式下是 `／`；放在命令词前面都当 `/`，所以 `、ls` 就是 `/ls`。
`/use`、`/close`、`/file`、`/pair` 的数字可以紧跟在词后面不加空格，
比如 `切换2`、`关闭2`；`２` 这样的全角数字按 `2` 算。

## 分几条发的消息

一句话拆成几条发很常见。会话空闲时，Ferry 不会拿到第一条就开跑：
每来一条新消息就重新等 2.5 秒，最迟在第一条之后 10 秒开跑。
等到的内容合成一个 prompt 交给 agent，只回一次受理回执，等的时候显示「对方正在输入」。
只发了图片或文件、没带文字时，会多等几倍时间，因为问题通常紧跟着单独发过来。

命令和审批回复照常立即处理，等待期间发 `/stop` 会把攒下的内容丢掉。
会话正忙时，消息照旧排队。配置里的 `input.gather` 控制等多久，设成 `"0s"` 就关掉。

## 语音消息

微信会自己把语音转成文字。Ferry 把转写交给 agent，并注明这是语音转写，
让 agent 对名字、标识符里的同音字多留个心；录音文件留在磁盘上，但不交给 agent，
因为它放不了。受理回执会复述微信听到的内容：听错了，就在 agent 动手前发 `/stop`（或「停」）。
微信没转出文字的语音会收到提示，请你重说或打字。语音只能用来拒绝审批，不能用来允许，见下文。

## 审批

agent 想做的事策略没法自己定时，你会收到一条消息：5 位字母编码、工具名、
说明，以及截断过的输入预览。用编码回复：

```text
y abcde
n abcde
a abcde
```

中文词也一样，编码前加不加空格都行：`同意 abcde`（或「允许」）允许一次，
`拒绝 abcde`（或「不同意」「不允许」）拒绝，`总是 abcde`（或「总是允许」「始终允许」）
总是允许。末尾带个句号也没关系。

**只有一个审批在等时，单独回 `y`、`n`、「同意」或「拒绝」就行。**
只有在不会弄错的时候，Ferry 才接受不带编码的词：这个审批属于前台会话，
它的请求至少送达了 3 秒，并且这个聊天里最近一分钟没有别的审批超时或被取消。
否则会请你带上编码，这个词也不会转给任何人。没有审批在等时，
同样的词就是发给 agent 的普通文本。「总是允许」一定要带编码。

语音消息只能用来拒绝，不能用来允许：微信转文字时可能把「不同意」的「不」丢掉。
要允许请打字回复。

`a` 只在 agent 本身支持「总是允许」时才给。**没人回的审批会在超时后按拒绝处理**，
并且会告诉你。只有审批人说了算：别人的裁决会被忽略，
指向一个已经结束的审批的裁决同样会被忽略。

预览会先过一遍掩码，像密钥、令牌这类东西只保留前 4 个字符。
但那是尽力而为，不是保证 —— 它终究是真实输入的预览。

## 配对

没用过这个 bot 的人，既拿不到权限也碰不到 agent。不管他发什么，
他只会收到一个 6 位配对码。审批人把它换成权限：

```text
/pair 123456
```

配对码 1 小时有效，同一个聊天最多同时挂 3 个。配对成功时双方都会收到通知。

## 回复窗口

微信只允许 bot 在一条入站消息打开的窗口内回复，而且次数有限。
所以 Ferry 会攒着发：普通进度按间隔合并成一条，
而审批请求和本轮的最终结果立刻发。

额度是按每条入站消息算的。Ferry 总会**留一个额度给审批请求**，
长输出按剩下的额度切分，最后一段标成「已截断」而不是把尾巴悄悄丢掉。
所以一轮特别啰嗦时，你看到的是更少更大的几条消息，而不是一串小消息。
